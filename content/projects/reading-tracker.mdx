I read a lot, but I used to forget most of it. The problem wasn't highlighting or note-taking — it was that I had no system for *revisiting* what I'd read.

This project is a minimal reading tracker: a structured CSV file, a few Python scripts to query it, and a weekly review habit.

## Why not just use an app?

Goodreads, StoryGraph, Notion templates — I've tried them all. The problem is that they're optimized for *tracking completion*, not for *connecting ideas*.

I wanted something that:

- Lives in plain text (portable, no lock-in)
- Connects to my notes (links to relevant entries in this garden)
- Is scriptable (I can query it how I want)
- Doesn't require an internet connection to log a book

A CSV file with a few columns turned out to be the right tool.

## The data structure

```csv
title,author,status,started,finished,rating,tags,garden_link
"Thinking Fast and Slow",Daniel Kahneman,read,2025-11-01,2025-12-10,5,"psychology,decision-making",
"The Mom Test",Rob Fitzpatrick,read,2026-01-15,2026-01-22,4,"startups,interviews",/notes/customer-interviews
"A Pattern Language",Christopher Alexander,reading,2026-03-01,,,"architecture,design",
```

Fields:

| Field | Description |
|---|---|
| `status` | `to-read`, `reading`, `read`, `abandoned` |
| `rating` | 1–5, only filled when finished |
| `tags` | comma-separated, aligns with garden tags |
| `garden_link` | link to a related note in this garden, if one exists |

## The scripts

A small Python script handles common queries:

```python
import csv
from datetime import date

def books_by_status(status: str, path="books.csv"):
    with open(path) as f:
        rows = list(csv.DictReader(f))
    return [r for r in rows if r["status"] == status]

def finished_this_year(path="books.csv"):
    year = str(date.today().year)
    with open(path) as f:
        rows = list(csv.DictReader(f))
    return [r for r in rows if r.get("finished", "").startswith(year)]
```

Run from the terminal:

```bash
python tracker.py --status reading
python tracker.py --year 2026
```

## The weekly review habit

Every Sunday I spend 10 minutes:

1. Updating the CSV with any books I finished or started
2. Checking the `to-read` list and picking next
3. If I finished something, writing a one-paragraph note — either standalone or linked to an existing note

The review is where the value is. Without it, the tracker is just a log. With it, it becomes a [[Tools for Thinking|thinking tool]].

## What I'd build differently

- Use SQLite instead of CSV (easier to query, handles commas in titles)
- Add a `notes` column for a one-line summary per book
- Generate a simple HTML page from the data — a public reading log

## Lessons

The best system is the one you'll actually maintain. I've abandoned more sophisticated setups than this one. The CSV has survived two years because the friction to update it is near zero.
