## The one refactor this needs

`getGardenStats()` in `stats.ts` calls `getAllContent()`, which uses `fs` and therefore cannot run in a browser. Same for `clusters.ts`.

**Extract the pure half.** Add `getGardenStatsFrom(items: ContentItem[]): GardenStats` containing all the existing logic, and make the current `getGardenStats()` a thin wrapper that reads from disk and delegates. Do the same for cluster detection.

This is a **pure refactor with zero behaviour change**. All 278 tests must still pass without modification. If any test needs changing, you have altered behaviour and should stop.

That seam is the whole reason this task is cheap: `xp.ts`, `stages.ts`, `species-assign.ts`, and `clusters.ts` are already pure and will run in a browser untouched.

## What to build

1. **`FsaGardenSource`** implementing `GardenSource` over a `FileSystemDirectoryHandle`. Treat `.md` and `.mdx` alike.
2. **Handle persistence** in IndexedDB so a returning user is not re-prompted. Verify the permission is still granted on restore; the browser can revoke it at any time, so `restore()` returning null after a successful earlier `connect()` is normal, not an error.
3. **`parse.ts`**: raw file text to `ContentItem`. Frontmatter parsing must work in the browser. `gray-matter` is already a dependency but check it bundles for the client; if it does not, write a small YAML-subset parser for the fields actually used (title, date, description, tags, type, maturity) and say so in your report.
   - **Missing frontmatter must not throw.** An Obsidian vault will have files with no frontmatter at all. Derive a title from the filename and default everything else. This is the common case, not an edge case.
4. **`ConnectGarden` component**: connect, show folder name and note count, disconnect. Handle every `GardenStatus` case with copy that explains what happened.
5. **`/garden` page**: connect, then render the creature, XP ledger, and cluster companions computed client-side. Reuse the existing `SpecimenPlate`, `XpBar`, `XpLedger`, and `CollectionGrid` components rather than building new ones.

## Non-negotiables

- **Non-Chromium must degrade, not break.** `isSupported()` false gets a clear explanation and the commits-only creature, never a crash or a dead button.
- **Nothing uploads.** No fetch of file contents to any server, ever. A reviewer should be able to grep for it and find nothing.
- Reading a large vault must not freeze the UI. Show progress if it takes a moment.
- A folder with no markdown at all reads as an explained empty state, not an error.
