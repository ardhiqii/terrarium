## The editor itself

Notion-feel: the user types, presses `Ctrl+B`, sees **bold**, and never sees `**asterisks**`.

That needs a real editor library rather than a textarea. TipTap and Milkdown are the usual answers. **Verify current versions and APIs before writing code, do not trust remembered APIs.** Report your choice and why; do not install without saying so.

If a library turns out to be too heavy for the value, a CodeMirror-style editor with markdown highlighting and shortcut keys is an acceptable fallback. Say which you picked and be honest about the tradeoff.

## Required behaviour

- **Create** with frontmatter as form fields (title, tags, maturity), never raw YAML in front of the user.
- **List** every note with tags and maturity, sorted sensibly.
- **Edit** existing notes.
- **Delete**, actually removing the file, with a confirmation since this destroys the user's data.
- **Rename**, see below. This is the hard part.
- **`[[` autocomplete** over existing note titles. Nearly free, and without it people do not link enough, which is the mechanic the whole product runs on.

## Rename: the part most likely to ship broken

Wikilinks reference notes **by title**, not by a stable id. So the title is a key living inside other people's files. Rename without rewriting and every inbound link dies **silently**: the build passes, pages render, links point nowhere, backlinks vanish, graph edges disappear, and XP drops. Nobody notices for weeks.

`rewrite.ts` must find every wikilink targeting the old title across every file and rewrite it. Four things that are each easy to miss and all fail invisibly:

1. **Exact target match only.** Renaming `[[Tools for Thinking]]` must NOT touch `[[Tools for Thinking Extended]]`.
2. **Preserve aliases.** `[[Old|display text]]` becomes `[[New|display text]]`, keeping the display text untouched.
3. **Both link forms.** `src/lib/utils.ts` resolves by title *and* by slug, so `[[Tools for Thinking]]` and `[[tools-for-thinking]]` both point at the same note. A rename must catch both.
4. **Case-insensitive matching**, because the resolver lowercases.

Reuse `parseWikilink` and `WIKILINK_REGEX` from `src/lib/utils.ts`. Do not write a second wikilink parser.

**Write the tests for these four cases first.** Each one is a silent-failure bug, which is exactly the class of thing a test suite exists to catch.

Also: renaming should update the file name *and* the frontmatter `title`, and the two must not drift apart.
