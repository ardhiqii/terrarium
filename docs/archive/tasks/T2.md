## Exact interfaces

```ts
// source.ts
import type { StageId, SpriteData, SpriteScale } from '../types'

/** A sprite resolved to something renderable. */
export type ResolvedSprite =
  | { kind: 'data'; data: SpriteData }
  | { kind: 'remote'; url: string; width: number; height: number; animated: boolean }

export interface SpriteSource {
  readonly id: string
  /** Never throws. Returns null when this source cannot supply the stage. */
  resolve(stage: StageId): Promise<ResolvedSprite | null>
}

export const LocalSpriteSource: SpriteSource
export const PokeApiSpriteSource: SpriteSource

/** Tries sources in order, first non-null wins. Never throws. */
export function resolveWithFallback(
  stage: StageId,
  sources?: SpriteSource[]
): Promise<ResolvedSprite>

/** Ordered source list. PokeApi first, Local last as the guaranteed fallback. */
export const SPRITE_SOURCES: SpriteSource[]
```

## Behaviour

1. **`LocalSpriteSource`** wraps the existing code-generated sprites via `getSprite()` and returns `{ kind: 'data' }`. This is the guaranteed fallback and must never fail.
2. **`PokeApiSpriteSource`** returns `{ kind: 'remote', animated: true }` with the GIF URL for the mapped id. Fetch metadata from PokeAPI only when it is not already cached.
3. **Caching is mandatory.** Write resolved metadata to `pokeapi-cache.json`, committed to the repo. After the first run a build must make **zero** network calls to PokeAPI. Their fair-use policy demands this and the penalty is an IP ban.
4. **`resolveWithFallback` never throws.** Network down, 404, malformed response, offline build: all fall through to `LocalSpriteSource`. A dead CDN must never break `npm run build` or render a broken image.
5. **`CreatureSprite`** renders `kind: 'data'` through the existing `Sprite` component, and `kind: 'remote'` as an image. Apply `image-rendering: pixelated` on the remote path, since these are 96px sprites being displayed larger. Integer scaling only.
6. **`next.config.ts`**: if you use `next/image`, add `raw.githubusercontent.com` to `images.remotePatterns`, and note that animated GIFs need `unoptimized` or the animation is stripped. A plain `<img>` with explicit width and height is also acceptable and may be simpler. Whichever you pick, **the sprite must still animate in the browser**, and you must confirm that by looking at it.

**Never commit a GIF or PNG sprite to this repo.** Only cached JSON metadata.
