## Build

A dev-only route at `/dev/sprites` rendering, using the existing `src/components/game/Sprite.tsx`:

1. All four creature sprites (`sporeling`, `mossling`, `bracken`, `heartwood`) side by side at **scale 3**, so the evolution line can be compared as a sequence.
2. The same four at **scales 1, 2, 3, 4** in a row each, to find where they stop reading.
3. All seven item sprites at **scale 2** and **scale 3**.
4. Idle animation running on the creatures.
5. Everything legible in both light and dark. Label each sprite with its id in Geist Mono.

Use the existing design tokens. This is a dev page, so it does not need to be beautiful, but it must not be misleading: put sprites on a neutral background, not a busy one.

## Then actually look

Use the `run` skill to launch the app and open `/dev/sprites`. **Screenshot it in both themes.**

Assess honestly, since the point of this task is judgment that a compiler cannot provide:

- Does the line read as a **progression** in silhouette and mass, or do the stages look like unrelated blobs?
- `bracken`'s fern gaps are only 2 to 3 pixels. Do they muddy at scale 2 (64px)?
- Does the run-length `<rect>` merge in `Sprite.tsx` render the same shape as the raw grid, or are there seams and gaps?
- Are the item sprites distinguishable from each other at scale 2, or do they read as generic brown lumps?
- Does the idle animation read as alive, or as a glitch?
- Contrast in dark mode: do the dark browns disappear against `--paper`?
