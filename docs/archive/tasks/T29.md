## Build

**1. `/u/[handle]`** — a public profile. Creature, stage, total XP, companion count, and when it last synced. Read through `SyncStore`.

A handle that has never synced is the **common case**, not an error: almost nobody will have synced. It needs a real page explaining what Terrarium is and how to get a creature, not a 404 and not an empty shell. Treat it as the main funnel for people arriving from a friend's profile.

Reuse `CreatureSprite` for the creature so it matches every other surface. It is an async server component, so `await` it.

**2. `/leaderboard`** — scoped to people the viewer follows on GitHub who have also synced.

`github-following.ts` reads the viewer's following list from the public GitHub API. Cache it; the list changes rarely and this must not hit GitHub on every page view. Every failure path returns an empty list rather than throwing, following the pattern already set in `src/lib/game/github.ts`.

**Never global.** A global board on public commit data would be farmed by bots within a week. Friend scope removes the incentive rather than trying to police it. Do not add an "all users" tab, even as a nice-to-have.

Signed out, or following nobody who has synced, are both normal states and need real empty states, not blank space.

Mark the viewer's own row.

**3. Nav link** to the leaderboard, shown only when signed in.

## Honesty requirement

Commit XP is verifiable against public GitHub data. Garden XP is **not**, because notes stay local and private.

Do not write copy claiming ranks are verified or authoritative. If you show a total, it is a self-reported number from a friend, and the interface should not pretend otherwise. Understated framing ("as reported by their garden") is fine; a trophy and the word "verified" is not.

## Design

Follow `DESIGN.md`: one accent, sharp corners, both themes, prose measure on reading sections, at most one small uppercase eyebrow per three sections, zero em-dash characters in visible strings.

Do not repeat the layout family used by `/companions` or `/guide`. Section-layout repetition is a pre-flight failure in this project and has already been caught twice.

Avatars come from GitHub. A missing avatar must not break the layout.
