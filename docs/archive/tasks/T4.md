This is the page that makes progress feel like progress, because it shows what is ahead.


`STAGES` is the full four-stage line. `state.stage.index` tells you how far along you are.

## What to build

**Route:** `/bestiary`, with `metadata` set (title and description), matching how other routes do it.

**The evolution line.** All four stages in order. Reached stages (`stage.index <= state.stage.index`) render normally with sprite, name, threshold, and blurb. Unreached stages render as **silhouettes**: same sprite, obscured, with the XP threshold visible so the goal is legible. Mark the current stage clearly.

For sprites use `CreatureSprite` (PokeAPI-backed, animated) for creature stages. It is an async server component, so `await` it.

**The item archive.** All seven items with unlock conditions, using `ItemDrawer` or a fuller layout if the page warrants more detail than the home page drawer. Locked items must show their requirement and progress. This is the engagement hook, so make the requirements read clearly.

**A stats summary.** Total XP, current stage, and the headline garden numbers from `state.stats`: notes, projects, words, links, backlinks, tags.

## Design constraints

- **Do not repeat the home page's layout family.** DESIGN.md section 6 and the taste skill both forbid two sections sharing a layout. The home page already uses a specimen plate plus a two-column ledger and drawer. The bestiary must compose differently, for example a horizontal progression line rather than a single plate.
- **Cell counts must match content counts.** Four stages means four cells, seven items means seven. No empty trailing cell. T3 already had to fix exactly this bug, so do not reintroduce it. Prefer `auto-fill` or a layout that cannot go stale if T9 adds items later.
- One accent colour. Sharp corners. Both themes.
- Zero em-dash characters in any visible string.
- Eyebrow budget: at most one small uppercase label per three sections.
- No game UI leaks onto note or project pages. This route is a game surface, they are not.
- Silhouettes for locked stages must not rely on colour alone to read as locked, since that fails for colour-blind users. Use opacity, a filter, or an explicit label.

## Edge cases

| Case | Expected |
|---|---|
| Stage 1 of 4 | Three silhouettes, thresholds visible |
| Max stage | No silhouettes, no broken "next" copy |
| All items locked | Page still reads as useful, not empty |
| `state.github === null` | Renders fine, garden stats only |
