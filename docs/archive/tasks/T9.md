# T9. Non-owner creatures: items and variants

**Depends on** T6, T8 (both done) · parallel-safe with T11
**Read first:** `AGENTS.md`, `ROADMAP.md` (the two known gaps), `DESIGN.md` section 3, `src/lib/game/items.ts`, `src/lib/game/repo-creature.ts`

Right now **every developer except the site owner gets a creature with an empty item drawer.** That is correct rather than leaky, but it guts the experience for exactly the people the extension exists to engage. This task fixes that.

## Gap 1: items leak owner data, so they were switched off

`items.ts`'s `getActiveDays()` calls `getAllContent()` unconditionally, reading the **site owner's local MDX publish dates**, and merges them into the Dew Vial streak regardless of whose `UnlockContext` is passed. There is no scoping parameter. T6 could not touch the file, so it disabled items for non-owners entirely.

**`items.ts` is now unfrozen for this task.** Fix it properly:

1. Scope `getActiveDays()` so garden publish dates are only included when the context actually belongs to the owner. Add whatever field to `UnlockContext` this needs. `src/lib/game/types.ts` is **unfrozen for `UnlockContext` only** — every other type in that file stays frozen, and changing one means updating every consumer.
2. Split items into **garden items** (need a garden: Spore Jar, Trowel, Field Ledger, Brass Compass, Pressed Frond, Hand Lens) and **commit items** (work from GitHub data alone).
3. Add at least **three commit-based items** so a non-owner creature has something real to chase. Ideas, pick or improve: a multi-day commit streak, commits across N distinct repos, a single day above N commits, a first commit older than a year. Use organic thresholds, not round marketing numbers.
4. Re-enable items for non-owner creatures in `repo-creature.ts`, passing only the items that apply. Garden items must not appear as permanently-locked noise on a creature that can never earn them.

**Verify no leak.** The existing bug is that owner data reaches a stranger's creature. Add a test that computes a non-owner creature and asserts none of the owner's garden numbers appear.

## Gap 2: the extension cannot draw item art

`CreatureState.items[].def.sprite` is a bare id string. The extension has no access to `SpriteData`, so its popup renders items as text pills instead of pixel art.

Fix by exposing item sprite pixel data through the API. Either inline the `SpriteData` in the JSON, or add an endpoint serving a sprite by id. Inlining is simpler but grows every response, so measure the size difference and pick deliberately. Say which you chose and why.

The extension side is out of scope. Just make the data available and note what changed for a follow-up.

## Gap 3: variant traits

From `DESIGN.md` section 3.5. The sprite should reflect the **shape** of the work, not only its size. A densely interconnected garden should look different from a sprawling one. For repo creatures, language or commit cadence could drive it.

This is the lowest priority of the three. **If time is short, ship gaps 1 and 2 properly and report gap 3 as not done.** A half-built variant system is worse than none.
