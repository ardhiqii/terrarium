## Priority 1: kill the meaningful survivors

**Not all survivors are worth killing.** Many are string-literal mutations replacing a user-facing `label` with `""`. The tests deliberately do not assert copy, which is a defensible choice, so those are noise. Do not write assertions on display strings just to raise a number. Gaming the metric is worse than a lower honest one.

**Do kill the logic survivors.** One confirmed example, `xp.ts:121`:

```
-  if (rawGardenXp + rawOtherXp === 0) continue
+  if (rawGardenXp - rawOtherXp === 0) continue
```

This survived. Under the mutant, any day where garden XP happens to equal other XP gets skipped entirely and scores nothing. That is a real bug the suite cannot see. Write a case that fails under it.

Work the HTML report and triage each survivor: **logic, boundary, or cosmetic**. Kill the first two. For cosmetic ones, say so and move on.

Target: **`items.ts` above 85%, overall above 85%.** If you cannot get there without writing meaningless assertions, stop and report the honest number with reasoning. An honest 80% beats a gamed 95%.

## Priority 2: test `github.ts`, the highest-risk untested module

`github.ts` has the single most load-bearing rule in the project: **it must never throw.** This site is statically built, so a thrown fetch takes down `npm run build`. That contract is currently protected by nothing.

Test every row, with `fetch` mocked. No live network calls, tests must be deterministic and offline.

| Case | Must produce |
|---|---|
| No token | Works via the events path |
| Network rejects | `null`, never throws |
| 403 rate-limited | `null`, falls back to cache |
| 404 handle missing | `null` |
| Malformed or truncated JSON | `null` |
| Corrupt cache file | `null`, treated as no cache |
| GraphQL returns an `errors[]` body | Falls through to the events path |

Also assert the invariant `xp.ts` depends on: **every key in `gardenCommitsByDay` exists in `commitsByDay` with a count no larger.** Violating it produces negative XP.
