## Build

**1. `SqliteSyncStore`** implementing `SyncStore` over `node:sqlite`. One table, handle as primary key, snapshot stored as JSON text. Create the schema on first use. Put the database file somewhere gitignored, and add the pattern to `.gitignore` if it is not already covered.

Handles are matched **lowercased**, since GitHub logins are case-insensitive and `Torvalds` and `torvalds` must not become two rows.

**2. `StubSessionProvider`** reading a handle from an env var (say `STUB_SESSION_HANDLE`) so a developer can act as any user locally. Returns null when unset, meaning signed out. Make it obvious in the code that this is not authentication and must never be the active provider in production; a comment is not enough, so also make the selection logic refuse the stub when `NODE_ENV === 'production'`.

**3. `buildSnapshot(state, clusters)`** producing a `SyncedSnapshot` from a `CreatureState`. This is the privacy boundary in code form: it must copy only the fields the contract names. Write a test asserting the output contains no tag names, note titles, or repo names, by checking the serialised JSON against a fixture whose content strings are distinctive. That test is the guard that stops a future change quietly widening what uploads.

**4. `POST /api/sync`** taking a snapshot from the signed-in user.
- 401 when signed out.
- **Validate against the closed shape and reject unknown fields**, rather than accepting and ignoring them. A client sending `{ noteTitles: [...] }` must get a 400, not a silent drop, so a mistake surfaces loudly.
- Reject a `schemaVersion` newer than `SNAPSHOT_SCHEMA_VERSION`.
- The handle comes from the session, **never from the request body**, or anyone can overwrite anyone.
- Rate limit per handle.
- `DELETE /api/sync` removes the user's data. Sync is opt-in and opting out must work.

**5. `GET /api/sync`** returns the signed-in user's stored snapshot, or 404 if never synced.

## The verification asymmetry, be honest in comments

Commit XP is verifiable server-side against public GitHub data. Garden XP is not, because the notes are local and private. Friend-scoped leaderboards make that tolerable, but do not write code or copy implying garden XP is verified. If a global leaderboard is ever added, this becomes a real problem that needs solving first.
