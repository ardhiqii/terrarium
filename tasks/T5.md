## The contract you must fill

```ts
export interface GithubStats {
  login: string
  totalCommits: number
  commitsByDay: Record<string, number>        // 'YYYY-MM-DD' -> count, all repos
  gardenCommitsByDay: Record<string, number>  // subset, this repo only, scores higher
  currentStreakDays: number
  fetchedAt: string                           // ISO timestamp
}
```

`gardenCommitsByDay` must be a true subset: every key also exists in `commitsByDay` with a count at least as large. `xp.ts` already relies on this and subtracts to find non-garden commits, so violating it produces negative XP.

## Exact interfaces

```ts
export interface GithubFetchOptions {
  /** GitHub handle, e.g. 'ardhiqi'. */
  login: string
  /** Repo name treated as "the garden" for the higher commit rate. */
  gardenRepo?: string
  /** Personal access token. Falls back to process.env.GITHUB_TOKEN. */
  token?: string
  /** Cache file path. Defaults to src/lib/game/github-cache.json. */
  cachePath?: string
  /** Refetch only if the cache is older than this. Default 6 hours. */
  maxAgeMs?: number
}

/** Never throws. Returns null on any failure. */
export async function fetchGithubStats(
  options: GithubFetchOptions
): Promise<GithubStats | null>

/** Returns null if missing, unreadable, or malformed. Never throws. */
export function readGithubCache(cachePath?: string): GithubStats | null

/** Best-effort. Swallows write errors. */
export function writeGithubCache(stats: GithubStats, cachePath?: string): void
```

## Behaviour

1. **Fetch** public commit activity for `login`. The events API and the per-repo commit-activity endpoints are both viable; pick one and document why in a comment. Only public data, no auth flow.
2. **Token** comes from `options.token ?? process.env.GITHUB_TOKEN`. **Unauthenticated must still work**, just rate-limited at 60 requests per hour. Never log or commit a token. Add `GITHUB_TOKEN=` to `.env.example` with a comment, and confirm `.env*` is gitignored.
3. **Cache** to JSON, committed to the repo. Builds must be fast, work offline, and survive rate limits. Refetch only when older than `maxAgeMs`.
4. **Streak.** `currentStreakDays` counts consecutive days ending today (or yesterday, so a day that has not started yet does not zero it) with at least one commit.
5. **Wire into state.** `getCreatureState()` already accepts `GithubStats | null`. Feed it the cached or fetched stats. It must keep working when that is null.

## The non-negotiable rule

**Every failure path returns null. Nothing throws.**

| Failure | Must produce |
|---|---|
| No token set | Works, unauthenticated, rate-limited |
| Network unavailable | `null`, falls back to cache if present |
| Rate limited (403 with the rate-limit header) | `null`, falls back to cache |
| Handle does not exist (404) | `null` |
| Malformed or truncated JSON response | `null` |
| Cache file corrupt | `null`, treated as no cache |

A GitHub outage must not break `npm run build`. The creature falls back to garden XP alone. This is the single most important requirement in this task, because the site is statically built and a throwing fetch takes the whole build down.
