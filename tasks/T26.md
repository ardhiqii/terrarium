## The rule that matters most

**Every number comes from the code at build time. Nothing is hardcoded in the page.**

Import `XP_RATES`, `STAGES`, `COMMIT_XP_DAILY_CAP`, `ITEMS`, and `CLUSTER_THRESHOLD` and render from them. If someone retunes a rate, this page updates itself.

This is not a nicety. `DESIGN.md` already drifted out of sync with `types.ts` on the stage thresholds once, and a guide that lies about the rules is worse than no guide.

Do not copy numbers out of `DESIGN.md`, `ROADMAP.md`, or the README. `types.ts` is the only source of truth.

## What to cover

**How XP works.** A table generated from `XP_RATES`. Then the intent in a sentence or two, because the numbers alone do not explain themselves: XP rewards *connection*, not volume. Wikilinks and backlinks score well, raw word count deliberately does not, so padding a note is a poor strategy. Commits are capped per day so a scripted loop cannot farm the creature.

**The four stages.** Rendered from `STAGES` with thresholds and blurbs. Show the sprites via `CreatureSprite`, which is a server component here so `await` it.

**Companions.** Bodies of work hatch companions; activity earns XP. A repo past a threshold, or a tag cluster of `CLUSTER_THRESHOLD` notes. A single note is a seed: it earns XP, hatches nothing, and may grow into a cluster later. A hatched companion inherits its cluster's XP rather than starting at stage 1.

**Items.** Rendered from `ITEMS`, with the garden and commit split made clear, since garden items only apply to the site owner. Each item's `requirement` string is already user-facing copy.

**Where XP comes from.** Notes and commits both, and honestly: without a `GITHUB_TOKEN` the unauthenticated path undercounts commits by roughly 10x, because GitHub's public events API no longer returns per-push commit counts.

## Design

This is a reading surface, not a game surface. Prose measure capped at `65ch`, EB Garamond for body, Geist Mono for numbers and tables.

Follow the standing rules: one accent, sharp corners, both themes, at most one small uppercase eyebrow per three sections, zero em-dash characters in any visible string, no empty grid cells at any breakpoint.

Do not repeat the layout family used by `/companions`. Section-layout repetition is a Pre-Flight failure.
